# Known limitations

Difference clouds identify eight-connected raster changes as bounding rectangles, with at most 200 eligible base-page regions. Small and completely off-base regions are excluded; partially clipped components retain their full component pixel count. Resolution, source annotation appearances, threshold and resampling affect results. Clouds need individual review/selection/approval and carry editable local evidence; they are not semantic or engineering acceptance. Synchronous region extraction adds mask/queue/preview memory beyond existing comparison allocations. No batch clouds, contour shapes, automatic merges or broad noisy-drawing/performance acceptance. See DIFFERENCE_CLOUDS.

Saved multi-file revision-set JSON resumes selected mappings only after unique exact-hash/page-count source resolution. It does not persist approval, PDF bytes, outputs or execution progress. Identical duplicate PDF snapshots on a side are ambiguous and must be removed before import. Standalone set plans share one operation/reason and retain source annotations; stale engineering labels still require independent review. See docs/REVISION_SETS.md. Earlier milestone statements about absent saved plans are historical; resumable execution and server history remain open.

Public test release: features are implemented and covered by automated tests, but have mainly been exercised on generated sample drawings. Validate results on your own drawings before relying on them, and keep originals.

- Authored rectangle, ellipse, line, arrow, highlight, ink, text, cloud, callout and text-based stamp annotations. Existing source annotations are displayed but not imported into the editable markup list. Text-based stamps implemented; image/PDF/dynamic stamps, cryptographic signatures remain unfinished. Same-page authored groups support atomic list-based actions; nested/canvas group transforms and foreign group import remain unfinished. Authored annotation layers are implemented with optional-content export; broad independent viewer acceptance remains open. Presets are a single local library; multiple/shared palettes and concurrent synchronization remain open. Callouts support two/three-point leaders and fixed Helvetica text; clouds use fixed scallop styling. CSV/PDF reports cover authored markups only. Text annotations support WinAnsi encoding; unsupported text fails explicitly.
- Numeric calibrated length/polyline/perimeter/area/angle/count/volume takeoffs are implemented with page/viewport scales and reviewed reference evidence. Drawing-based point capture, SVG geometry previews, endpoint snapping, presets, derived-quantity formulas and standard PDF measurement-annotation export are available; midpoint and straight-line intersection snapping is included (intersections skipped above 6,000 segments per page); JSON import, curve-intersection and layer-aware snapping are not. CSV/XLSX quantity exports include calibration evidence; XLSX rejects cell strings over 32,767 characters or invalid XML controls. Native Excel acceptance and large-workbook benchmarks are pending; openpyxl reports a missing default style but reads the data successfully. JSON export and opt-in recovery retain the editable model; quantities recalculate from evidence. Synthetic numerical checks are not engineering certification.
- Collaboration (self-hosted server; desktop via `--server`) and a reviewable sheet-index assistant exist; see COLLABORATION and COMPLETION_GATE. OCR covers English, Spanish, French and German and runs on the CPU (seconds per large sheet). No editing of existing PDF content text; no 3D PDF (U3D/PRC) viewing.
- Redaction rebuilds every affected page as a ~200 dpi image (36x48 in sheets ~150 dpi), so that page loses vector sharpness; its remaining text is re-added as invisible searchable text (WinAnsi only); bookmarks, tagged structure, document JavaScript and title/subject/keywords are dropped from redacted copies.
- Digital signatures: adbe.pkcs7.detached SHA-256 with PKCS#12 RSA or P-256/P-384 keys, appended as incremental updates (multiple signatures, DocMDP certification, RFC 3161 timestamps via the self-hosted server's configured TSA). Trust is checked against certificates the user supplies; revocation against supplied CRLs, CRLs/OCSP responses embedded in the PDF, or live OCSP through the self-hosted server (only to responders in OPENDRAFT_OCSP_HOSTS). Long-term validation data and archival document timestamps (PAdES-LTA, via the server's TSA) can be added.
- Annotation import converts standard markup types; measurement annotations, non-WinAnsi text, polygon outlines and unknown types stay as uneditable PDF annotations, and custom stamp artwork becomes a text stamp.
- Forms: filling and field creation (no radio-group or list-box creation); XFA forms are refused; signed forms cannot be filled.
- Windows installers are not code-signed, so SmartScreen warns on first run. Opt-in local recovery retains original sources and editable markup state; undo history, tab coordination, storage eviction and sudden power-loss durability are not covered.
- No full PDF conformance guarantees. Structural detection refuses apparent signed/certified rewrites and XFA editing; it does not validate cryptographic signatures. Untouched downloads retain identical bytes. Full single-source reordering, rotation and authored-annotation export retain the original catalog in tested fixtures; partial/multi-source organization can omit catalog structures.
- Encrypted/malformed documents can fail; encrypted editing is unsupported.
- Large-format performance, scanned documents, specialized fonts/color profiles, optional content, forms and attachments require a compatibility corpus. Browser rendering is not independent export validation.
- Browser support, accessibility and Windows desktop support are not certified by one Chromium test run.
- Package vulnerability scan is not a security audit or complete license clearance.

- Independent-reference verification rejects the original endpoint pair (including reversed/near-coincident copies), but cannot establish that a different reference distance is independently known. Verified/accepted quantity state is not persisted or enforced before measuring/export. Calibration changes that affect existing measurements now require a preview of old/new quantities and scale evidence plus explicit approval bound to that candidate. This local review is not a persisted acceptance/audit record. These remain measurement completion blockers.
- Rotation, markup and authored flattening retain source Info/XMP in tested fixtures, including source Producer/dates and custom fields. Those dates are not an OpenDraft edit audit trail. Partial/multi-source assembly retains stable primary-source Info/XMP but can omit other catalog structures; broad metadata interoperability remains unverified. See docs/PAGE_ORGANIZATION.md.

Preset libraries retain tool/style/contents unencrypted in browser localStorage independently of PDF recovery. Limits: 200 entries/1 MiB; duplicate import rejects the entire merge. Stale-tab guard does not guarantee atomic multi-tab transactions. See docs/MARKUP_PRESETS.md.

Stamp appearances use standard names and independently drawn Helvetica-Bold text/borders, auto-fit 8–36 points with explicit rejection if too small. No cryptographic identity or approval workflow. CSV markup reports now have an appended 18th Stamp appearance column. See docs/STAMPS.md.

Groups require at least two same-page authored annotations. Selecting one member expands the complete group. Individual edits require ungrouping; locked members block changes except explicit unlock. PDF grouping uses IRT/RT Group; broader interactive viewer acceptance remains open. CSV reports append Group ID as column 19. See docs/MARKUP_GROUPS.md.

Authored layers are local editing controls, not security permissions or redaction. Foreign source layers/annotations are not imported into the editable authored model; measurements are separate. Flattened layers remain toggleable. Source optional-content preservation is scoped to layout-preserving export, not page assembly. Full independent viewer certification, concurrency, installer and complete release gates remain open. See docs/MARKUP_LAYERS.md.

Independent renderer limitation: PDFium 5.14.0 renders hidden authored annotations despite /OC membership on both annotation and appearance Form. Hidden flattened content is correctly absent and visible annotated/flattened content matches. PDF.js hides and toggles both correctly. Saved hidden annotations may therefore appear in other viewers; no broad layer interoperability is claimed. Reproduce with scripts/generate-layer-validation.mjs and scripts/independent-layer-check.py; the checker deliberately exits nonzero for this mismatch. This remains an unresolved completion-gate item.

The synthetic PDFium visibility defect described above is now resolved: appearance drawing operators carry optional-content BDC/EMC and resources. Unchanged independent checker passes14/14; hidden annotated and flattened outputs equal baseline on rotations0/90. This supersedes the two recorded failures for that fixture, not the broader independent-viewer completion requirement.

Markup review controls are session-only, shared by open tabs and do not filter report exports. Group selection survives filtering; the UI counts excluded selected members because group actions still include them. Saved/shared filter views, threaded comments, filtered-report exports and large-list/screen-reader acceptance remain open. See docs/MARKUP_REVIEW.md.

Local comment/reply CRUD is implemented for authored annotations. It does not provide authenticated authorship, multi-user synchronization or immutable audit. Foreign PDF comments are displayed by independent viewers but not imported into the editable model. Flattened export removes authored threads; save editable PDF/report to retain them. Unicode comment metadata/CSV works; unsupported WinAnsi PDF-report characters fail explicitly. See MARKUP_COMMENTS for bounds and pending acceptance.

## Revision comparison
Read-only raster overlays/differences support manual similarity transforms and reviewable automatic similarity candidates for two selected pages; they do not verify engineering changes. DPI/threshold/antialiasing/alignment can hide or exaggerate changes. Defaults from source PDFs apply; viewer layer toggles are excluded. Per-run input/union limit4M pixels and8192 per side;64MiB per source, not an aggregate memory guarantee. Cancellation cannot interrupt the bounded synchronous comparator. Exports are raster evidence, not vector revisions; JSON hashes are not authenticated audit/signatures. Automatic scale/rotation/translation candidates can be wrong on repeated patterns; perspective/nonuniform registration, batch pairing, revision history, clouds and slip-sheet replacement remain open. Pinned JSFeat0.0.8 is an old dependency without established current maintenance; see ALIGNMENT_ACCEPTANCE. See REVISION_COMPARISON for precise semantics and remaining acceptance.

JSFeat package-level MIT text is verified, but embedded qsort/FAST/YAPE/OpenCV provenance still needs release review. Full upstream text notices are retained in browser assets and desktop packaging inputs. No complete license clearance is claimed.

Batch revision review compares selected sheets from two open source snapshots, with label/order/manual one-to-one matching. No folders/multi-file sets, region matching, persisted approvals/saved batches, semantic difference annotations, batch auto-registration, batch recovery or slip sheets. Rendering uses default PDF visibility/display appearances. Raster/aggregate budgets are documented; maximum batch throughput/aggregate boundary acceptance remains unverified. Synchronous bounded comparison/ZIP cannot be interrupted mid-operation. See BATCH_REVISION_REVIEW.

Slip-sheet replacement preserves target document annotations at fixed coordinates and excludes donor annotations/forms. Retain-authored requires exact viewBox/UserUnit/final-rotation match; matching dimensions do not verify registration. Replaced-page scales/takeoff are cleared. Donor OCG configurations/cross-page resource dependencies reject; tagged-PDF semantics and broad catalog compatibility are not accepted. Local journal is undoable, mutable, recovery-persisted and separately exportable, not embedded in standalone saved PDF or a tamper-proof audit. No insertion/superseded/multi-file revision management yet.


## Revision insertion limitations — 2026-10-21
Implemented scope is reviewed two-open-PDF insertion with explicit superseded appearance. Old navigation remains old-sheet navigation. No automatic markup or measurement transfer. Selected old takeoff is removed on approval. Superseded stamps are editable and may cover drawing content; tiny pages reject. Sources inspect at 200 pages/64 MiB; a >200-page result cannot enter another slip review. Donor layers/cross-page resources reject. Partial/multi-base catalog preservation remains weaker. No new installer acceptance, collaboration or production-readiness evidence. See REVISION_INSERTION.md.


## Saved revision plan limits — 2026-10-21
Only slip-sheet plans for two exact open PDF snapshots. No BCX compatibility, source fuzzy-rebinding, folder/multi-document execution, batch comparison reuse, cloud/shared approvals or plan library. Version1 imports cap256KiB,200pages/source,100pairs; approval never persists. See docs/REVISION_PLANS.md.


## Multi-file drawing sets — current scope, 2026-10-21
Standalone file/folder revision sets now exist; this supersedes earlier statements that all multi-file execution is absent. Open workspaces, their authored markups/takeoff/journals/recovery and original disk files are untouched. Source PDF annotations and old measurement labels may be retained and stale; matching geometry is not engineering acceptance. No legacy PDF engineering-label clearing or quantity transfer is claimed; independently calibrate new sheets. Per-file inspection failures/unselected sources remain UI evidence, while archive results cover requested jobs only. Failed job journal fields record requested operations, not committed revisions.
Cancellation acts at read/library/job stage boundaries; synchronous PDF/ZIP calls are not interruptible. 64 MiB/source,256 MiB/input,128 MiB/output caps concern encoded bytes, not RAM; broad aggregate performance acceptance remains open. Focused browser 4/4 and independent synthetic 154/154 checks pass; full browser/hidden-desktop regression 71/71 also passes, then two additional focused folder/read-race checks passed separately. These tests do not establish aggregate resource/performance or broad professional interoperability acceptance. No saved/resumable multi-file library, region matching, shared approval, immutable archive or full parity. See docs/REVISION_SETS.md. Full original gate remains open.

## Release candidate 0.1.0 (2026-10-21)
- Collaboration: single server process, in-memory sessions (sign in again after restart), no SSO/password reset, plain HTTP behind a required TLS proxy, not available in the desktop build; page organization/revision journal/comparison are local-only. Remote edits enter local undo history.
- Assistant: sheet numbers/titles only; heuristic CPU engine can mislabel; model output is untrusted and validated; exports only.
- Snapping: painted path endpoints only (no intersections/midpoints/text), optional-content visibility not evaluated, 50,000 points per page.
- Measurement annotations: angle/count omitted; not re-imported; UserUnit not folded into conversion factors.
- Installer unsigned with default icon; installer bytes not reproducible (archives are). User data is retained on uninstall.
- Performance evidence is from a 64 GB Ryzen 7800X3D host with synthetic vector sheets; scans/complex fonts untested.
