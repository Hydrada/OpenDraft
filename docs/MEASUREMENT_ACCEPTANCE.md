# Calibrated measurement engine acceptance

2026-10-21. Pure CPU geometry foundation; no engineering-use certification implied. Geometry is in **unrotated PDF default user space**; UI must invert the actual PDF viewport transformation before supplying points. Zoom, screen pixels, page rotation and display DPI are not calibration units. Calibration converts a known distance to metres per PDF coordinate unit, retaining its two reference points, known distance and unit. Recovered ratios are recomputed and checked against that evidence.

## Supported calculations
Length (two points), open polyline, simple polygon perimeter/area, interior angle at middle of three points (0–180 degrees), explicit point count, and prismatic volume (polygon area times known uniform depth). Linear units: mm, cm, m, km, international in/ft/yd. Area/volume output use squared/cubed linear units. Angles and counts do not need a distance scale. Count counts supplied observations, including intentional repeated coordinates; it does not detect symbols automatically.

International definitions use 1in=0.0254m, 1ft=0.3048m, 1yd=0.9144m. Sources checked 2026-10-21: [NIST Handbook 44 Appendix C](https://nvlpubs.nist.gov/nistpubs/hb/2026/NIST.HB.44-2026.pdf), [NIST revised conversion factors](https://www.nist.gov/pml/us-surveyfoot/revised-unit-conversion-factors). Legacy US survey foot is not accepted as `ft`.

## Scale resolution and boundaries
At most one page-wide scale per page. Viewport rectangles have closed boundaries. A measurement wholly inside one viewport uses its scale ahead of a page-wide scale. Crossing/touching multiple viewport regions, crossing out of a viewport, or spanning a viewport even with both endpoints outside fails with an ambiguity error. Split such geometry explicitly; do not average or silently use the page scale. Polygon area/volume also rejects an enclosed different-scale inset. A perimeter entirely outside an enclosed viewport can use page scale because its measured boundary does not enter that viewport.

## Acceptance tolerances
Independent known-line verification defaults to relative error <=0.001 (0.1%). The operator must select a second authorized reference; rechecking the same calibration line is not independent evidence. Synthetic geometry tests require relative/absolute numeric error <=1e-11×max(1,expected) for normal cases, substantially tighter than the workflow tolerance. This only tests arithmetic, not raster quality, snapping, distorted scans, or operator calibration error. No result is rounded inside the engine; formatting must retain adequate precision and exports must retain the raw value.

Fixtures exercise 3-4-5 length; orthogonal polyline; rectangle/triangle/concave area and perimeter; SI/imperial conversion; uniform-depth volume; angles/counts; rigid rotation/translation invariance; large-origin small-shape area; viewport boundary/crossing/overlap/enclosed-inset rejection; selfintersection, repeated-edge and degenerate geometry rejection; forged recovered ratios; quantity factor/waste bounds.

Run `node --test tests/measurements.test.mjs`. Actual results belong in TEST_RESULTS.md; this document defines scope and acceptance, not an unexecuted success claim.

## Bounds and limitations
Coordinates finite and absolute <=1e9; reference/segment separation >=1e-7 PDF units; polygons <=2000 vertices; other paths/counts <=10000 points; <=1000 stored calibrations; calibration ratio in [1e-12,1e12] metres/PDF unit; output quantity <=1e18. Degenerate polygon area/orientation tolerance is 1e-12×max(1,x-span,y-span)². Extremely thin or precision-limited polygons can be rejected deliberately. Self-touching polygons, holes, curved geometry, spherical/geographic geometry, nonuniform/projective distortion, automatic symbol count, density/material databases and arbitrary user formulas are unsupported. Quantity arithmetic supports a bounded nonnegative multiplier and 0–1000% waste; it never evaluates script text. Volume assumes constant depth and does not infer engineering geometry. Persisted measurements/calibrations must stay associated with their source pages; changing a calibration must require explicit review rather than silently altering accepted quantities.

## Quantity CSV exchange
Export takeoff CSV produces one row per measurement with one-based page, raw unrounded value and dimensional unit, geometry in unrotated PDF user space, depth when present, and the resolved scale reference/viewport evidence. No aggregation combines unlike units. Scale-independent count/angle rows have empty calibration columns. Model validation and recomputation precede export; untrusted text beginning with spreadsheet formula prefixes receives an apostrophe without changing the source model. Numeric coordinates remain JSON arrays. Empty workspaces export a header only. CSV is an exchange report, not a replacement for the editable JSON model. XLSX now uses the same validated rows with typed numeric cells and literal strings, a frozen header and wrapped text. Cell text exceeding 32,767 characters or containing invalid XML controls fails explicitly rather than truncating evidence. Native spreadsheet acceptance and large-workbook performance remain pending.

Reproduce the independent standard-library check after the measurement E2E download using `python scripts/check-takeoff-csv.py test-results/takeoff-quantities.csv`.

Independent XLSX reader: `python scripts/check-takeoff-xlsx.py test-results/takeoff-quantities.xlsx test-results/takeoff-quantities.csv` requires openpyxl (validation-only, not shipped). Exports are snapshot values; editing cells does not recalculate OpenDraft geometry.

## Drawing-based capture
Pick calibration/verification points or measurement points on the rendered sheet. Two-point references and lengths, and three-point angles finish automatically; polygon, polyline and count drafts require Finish picking points. Backspace removes the latest point while the overlay has focus; Escape cancels. Capture fills coordinate fields only and does not save a calibration/measurement. Calibration review must be checked again after picking. Zoom/rotation/page/document changes cancel unfinished drafts. Numeric entry remains available; there is no snapping or inferred engineering geometry. Stored geometry is a local SVG preview and is not embedded in saved PDFs.

Verification rejects the original reference endpoint pair in either order, with 1e-7 PDF-unit endpoint tolerance. Different geometry alone does not establish independent source evidence. Verification acceptance is still incomplete: persisted accepted/verified quantities are not implemented. Passing synthetic capture tests does not close those requirements.

## Recalibration impact approval
Use Review calibration impact after checking the known reference. The preview lists each existing measurement whose quantity or resolved calibration evidence would change, with raw old/new values, units and evidence. Save requires Approve reviewed quantity changes for that exact candidate and current takeoff state. Edits to calibration inputs clear both reference review and impact approval; takeoff/page context changes invalidate pending approval. Ambiguous or invalid scale proposals fail before approval. Counts/angles without dimensional scales are unaffected. Approved calibration and recomputed quantities enter one undo/redo command; cancelled/rejected previews do not change stored state. Approval is currently local and transient, not a persisted accepted-quantity or audit record.
