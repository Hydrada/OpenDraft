# OpenDraft PDF foundation review

Research date: 2026-10-21. Primary upstream sources were inspected. This is an engineering selection review, not a completed legal audit or a vulnerability-free certification. Actual distributed versions and their transitive assets must be inventoried from the lockfile and release package.

## Initial selection

Use **PDF.js for browser rendering/text extraction** and **pdf-lib behind a replaceable document-edit adapter** for the first local-only slice. Both run in JavaScript without a mandatory service. This reduces native packaging work and preserves a permissive path. It does not provide a professional construction editor by itself. Native PDFium and server-side PDFBox/QPDF remain candidates after interoperability and performance benchmarks. No AGPL engine is included by default.

| PDF.js | Apache-2.0; retain license, applicable notices, and modification notices. Audit bundled fonts, CMaps, WASM and other assets separately. [License](https://github.com/mozilla/pdf.js/blob/master/LICENSE) | Browser rendering, text extraction and viewer building blocks. Does not supply OpenDraft's complete document editing, measurement or collaboration model. | Mozilla publishes a [security policy and advisories](https://github.com/mozilla/pdf.js/security), including a July 2026 arbitrary-JavaScript advisory. | PDFium | Current [LICENSE](https://pdfium.googlesource.com/pdfium/+/refs/heads/main/LICENSE) contains BSD-style and Apache-2.0 terms; third-party dependencies have additional notices. [Build documentation](https://pdfium.googlesource.com/pdfium/+/refs/heads/main/README.md) uses Chromium GN/Ninja/Clang tooling. Chromium's sandbox is not automatically inherited by a standalone binding. **Benchmark candidate**, not initial runtime. |
| PyMuPDF | [COPYING](https://raw.githubusercontent.com/pymupdf/PyMuPDF/main/COPYING) is AGPL-3.0; Artifex offers commercial licensing through its product channels. | Python wrapper around MuPDF with rendering, extraction, annotations, drawing and optional-content APIs. [Feature documentation](https://pymupdf.readthedocs.io/en/latest/about.html). | pypdf | BSD-style license verified in [upstream LICENSE](https://raw.githubusercontent.com/py-pdf/pypdf/main/LICENSE); retain copyright, terms and disclaimer. | Pure-Python document manipulation, extraction, page transformations and merge/split. [Repository](https://github.com/py-pdf/pypdf). No renderer; not sufficient for the interactive canvas. | [Security policy](https://github.com/py-pdf/pypdf/security) applies fixes to the latest version and publishes advisories. Potential backend/migration utility; **not initially required**. |
| QPDF | Current releases Apache-2.0. Preserve notices and review bundled dependencies. [Repository/license](https://github.com/qpdf/qpdf). Older-version assumptions must not be carried forward. | Strong structural transforms, merge/split, encryption and linearization. [Documentation](https://qpdf.readthedocs.io/en/stable/overview.html) explicitly distinguishes it from a renderer or semantic content editor. | Current GitHub [security page](https://github.com/qpdf/qpdf/security) displays no SECURITY.md or published advisories; that is not proof of no vulnerabilities. Release monitoring and isolated subprocess limits required. **Future structural validator/worker candidate.** |
| Apache PDFBox | Apache-2.0. Review dependencies and optional codecs individually. [Official overview](https://pdfbox.apache.org/) | Java creation/manipulation/extraction, rendering/printing utilities, signing and PDF/A-1b preflight. Good self-hosted worker candidate, JVM cost for a local browser slice. | Official site lists 2026 releases and a [security page](https://pdfbox.apache.org/security.html). **Future service and independent interoperability candidate**, not bundled yet. |
| LibreOffice conversion | MPL-2.0 with Apache-derived and many differently licensed components. Release-specific LICENSE must be reviewed; modified covered files carry source obligations. [Licensing](https://www.libreoffice.org/licenses/) | Useful future Office-to-PDF conversion process. Fidelity is document/font dependent; not a construction rendering engine or lossless arbitrary PDF editor. Run separately with an isolated profile and bounded jobs. | Maintains [security policy](https://www.libreoffice.org/security-info/) and [advisories](https://www.libreoffice.org/security/). Conversion of untrusted Office/PDF documents is a substantial attack surface. **Deferred**, no bundled office runtime in initial slice. |
| pdf-lib | MIT; preserve copyright/license. [Repository and limitations](https://github.com/Hopding/pdf-lib) | Pure JS page insertion/removal/copy, drawing, forms and serialization. [API overview](https://pdf-lib.js.org/). Added text/graphics are page-content edits; this is not editable standard annotation interchange. No general existing page-text editing or encrypted-document support. | [Releases](https://github.com/Hopding/pdf-lib/releases) shows latest release 1.17.1. Sparse release cadence is a maintenance risk; adapter containment, malformed-input regression tests, resource limits and replacement plan required. **Selected provisionally for narrow edits**, not a permanent commitment for all phases. |

## Existing applications investigated

| Application | Relevant reuse or lesson | Boundary |
| --- | --- | --- |
| [Xournal++](https://github.com/xournalpp/xournalpp) | Established cross-platform handwriting/PDF annotation, selection, shapes, layers, backups and plugins. Strong reference for independent workflow testing. | GPL-2.0 repository; copying/integrating code changes licensing obligations. Its note model and exported drawings do not establish construction takeoff parity or standard editable PDF annotation round trips. No code/assets copied. |
| [Okular](https://okular.kde.org/) | Mature document viewer with annotation workflows; useful independent-viewer test target. | KDE source host returned 403 during this review, so exact file-level license and distribution inventory remain unverified here. Not selected for embedding. |
| [Stirling PDF](https://github.com/Stirling-Tools/Stirling-PDF) | Self-hosted browser/API platform with many PDF operations. Evaluate API interoperability rather than rebuild every batch operation. | Current [license](https://raw.githubusercontent.com/Stirling-Tools/Stirling-PDF/main/LICENSE) is MIT only outside listed separately licensed directories, including engine, desktop and proprietary paths. README explicitly says open-core. Whole-repository permissive reuse is not established. No dependency selected. |

No inspected application establishes complete construction markup, calibrated takeoff, revision workflows and offline collaboration parity. This review is a shortlist, not an exhaustive search of every GitHub project.

## Required follow-up before production

- Freeze actual versions, hashes, license texts, NOTICE files, third-party fonts/codecs and SBOM for every distributed artifact.
- Run dependency advisory audits and malformed/encrypted/oversized PDF regression suites. Browser execution is a security boundary, not a guarantee against denial of service.
- Validate preserved outlines, attachments, links, layers, forms and signatures across edits. Rewriting a PDF can invalidate signatures; never promise preservation without evidence.
- Independently render exports with a different engine. Re-reading with the writing library alone cannot establish interoperability.
- Benchmark large drawings and memory use before selecting permanent engine/native deployment architecture. No comparative performance result has been measured by this review.
