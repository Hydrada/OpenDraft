# Reviewed batch revision comparison

This advances Project 1 Phase 4; the full completion gate remains unsatisfied.

## Workflow and scope
Open two PDFs, choose Batch revision review, select unique PDF page labels or page order, and prepare the plan. Labels normalize NFC, whitespace and Unicode uppercase; duplicate or absent labels are never guessed. Every base page has an editable revision selection or explicit exclusion. Each revision page can appear only once. Review unmatched sheets and per-pair scale, clockwise rotation and point offsets, then approve and run. Any control change revokes approval; changes during a run cancel it and prevent stale output. Review applies to the exact captured source bytes, not engineering correctness. This approval is transient, not a persisted acceptance/audit record.

Rendering uses isolated workers and the PDF default layer visibility/display annotation appearances. Sequential pairs produce raster differences or overlays. Similarity transforms reuse the individual comparison coordinate/resampling rules; manual point offsets round to output pixels. Whole transformed unions are retained. Source bytes, markups, calibration, takeoff and undo history are unchanged. Automatic alignment remains available separately per-page, not silently applied across a batch.

The ZIP contains generated numeric PNG paths, comparisons.pdf when at least one pair succeeds, manifest.json and summary.csv. The image-only PDF embeds the same manifest. Each success records source/page geometry, transform, output geometry, changed-pixel count/bounds, PNG SHA-256, output PDF page and physical dimensions. Failures carry their reason; unmatched/excluded pages are separate lists. No successful pages means JSON/CSV only. Cancellation rejects the whole job and retains no downloadable partial archive. CSV is quoted Unicode text with dangerous formula prefixes neutralized, including after whitespace/control characters. Untrusted labels use text nodes in the UI and never file paths.

## Resource limits
Each source: 64 MiB, 1–200 pages. Selected pairs: 1–100. DPI: 36/72/108/144. Threshold: integer 0–255. Each source raster and union: 4,000,000 pixels and 8192 pixels per side, checked before canvas allocation. Batch budget: 40,000,000 processed output-union pixels; 32 MiB encoded PNGs; each PDF and total ZIP at most 64 MiB. Source snapshots are copied synchronously and SHA-256 rechecked before processing; page count and labels are independently read again. Per-sheet failures continue; global packaging failure yields no archive. Synchronous comparison/ZIP work cannot be interrupted until the bounded operation returns. These are resource guards, not performance benchmarks or guarantees against every malformed PDF.

## Acceptance and limits
Known synthetic sheets cover reordered label mapping, duplicate ambiguity, excluded/unmatched pages, exact 800-pixel difference and identical sheets, individual oversize failure, all-failed archive behavior, similarity geometry, CSV formula protection, changed source-hash rejection, stale review, cancellation and byte-identical source exports. Independent pypdf/PDFium/Pillow checker verifies ZIP paths, expected page mapping/counts, source/PNG hashes, CSV, attached manifest, physical geometry and full PDF raster versus PNG. Consult TEST_RESULTS for actual latest runs. Aggregate 40M/32MiB/64MiB boundaries and maximum-size batches are not benchmarked acceptance evidence yet.

Missing original scope includes folder/multi-document sets, filename/text-region matching, saved batch jobs, batch automatic alignment review, semantic change annotations in the markup list, persisted revision history, slip sheets, recovery/resume of a batch, broad authorized drawing corpora and production performance acceptance.
