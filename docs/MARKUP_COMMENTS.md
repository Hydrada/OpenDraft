# Markup comment threads

Select an authored markup to read its comments. **Add markup comment** creates a top-level entry; choose an existing comment and use **Reply to selected comment** for a child. The author is a local display name, not a verified identity. Comments on a group member belong to that individual annotation, not every member.

**Update selected comment** changes its author/body while retaining its identity, parent and creation time. **Delete selected comment and replies** removes its complete descendant subtree. Undo/redo restores the thread atomically. **Clear comment selection** starts a new draft. Annotation and owning-layer edit locks block adding, editing and deleting comments; unlock the relevant annotation/layer first.

Threads follow existing annotation state through history, page remapping and opt-in unencrypted browser recovery. Editing markup geometry/properties preserves its comments. Deleting the markup removes its discussion. Undo history itself is session-only. Presets retain tool appearance/content, not discussion or reviewer identities. Text review filtering includes comment IDs, authors and bodies; list badges count comments.

Limits: 100 comments per annotation, 5,000 across the workspace, and 2,000,000 total comment author/body characters. Authors contain 1–200 trimmed characters; bodies contain 1–10,000 trimmed characters. Unsupported controls, malformed Unicode, duplicate IDs, dangling/forward/cyclic parent references and invalid timestamps reject the whole candidate. Parents precede replies in stored order. A local editing operation cannot predate the markup's latest modification; this is validation, not an authenticated audit trail.

Saved editable PDFs export comments as standard Text replies with `/IRT` and `/RT /R`, separately from `/RT /Group` annotation membership. Nested replies point to their parent comment; top-level comments point to their owning annotation. Reply metadata retains Unicode author/body and creation/modification dates. NoView and non-printing flags avoid standalone note icons changing the drawing. Existing foreign source annotations remain separate. The [Adobe PDF 1.6 reference, markup annotation reply entries](https://opensource.adobe.com/dc-acrobat-sdk-docs/pdfstandards/pdfreference1.6.pdf) distinguishes threaded replies from groups; interactive reply presentation still needs broader viewer acceptance.

**Flatten OpenDraft markups removes authored comment objects along with editable annotation objects.** Save an editable PDF or export a report to retain discussion evidence. Flattening leaves the current editable workspace unchanged. It is not redaction; previously saved copies and recovery can retain comments.

CSV preserves the first 23 columns and appends **Comment count** (24) and **Comments JSON** (25). JSON preserves each identity, parent, author, body and timestamps. Reports include every authored annotation and comment regardless of list filters. PDF reports paginate comment evidence; their existing WinAnsi font rejects unsupported Unicode explicitly. Unicode remains available in CSV, recovery and editable PDF reply metadata; it is not silently substituted in reports.

Local comments do not provide simultaneous editing, authentication, permissions, notifications, immutable audit history or offline conflict resolution. Foreign PDF comment import/editing, rich text, attachments, mentions, authenticated author attribution, broader viewer/browser/screen-reader tests and large-thread performance acceptance remain open. Actual executed tests and independent reader versions are recorded in TEST_RESULTS.md. Reproduce independent fixtures with scripts/generate-comment-validation.mjs and scripts/independent-comment-check.py in an isolated validation environment.
