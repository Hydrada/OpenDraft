# Reviewed drawing revision sets

Choose **Revise drawing set** without opening PDFs in document tabs. Select current and revision PDF files, folders, or both. Folder selection includes browser-exposed descendants; non-PDF files are ignored and counted. OpenDraft reads the selected files and downloads new results. It does not overwrite disk files, edit open workspaces, import their authored markups/takeoff, or add entries to their undo/recovery state.

## Prepare and review

1. Select 1–20 PDFs on each side and choose **Prepare drawing set**. File metadata limits are checked before `arrayBuffer()` reads. Each PDF is inspected sequentially; failures appear beside the individual file and successful inspections remain available.
2. Review the revision file assigned to each current drawing. Suggestions require a unique NFC-normalized, trimmed, uppercased basename on both sides. Duplicate filenames remain unmatched. Manual file assignments must be one-to-one among selected jobs.
3. Choose unique PDF page labels or explicit page order, then review each sheet assignment. Label matching normalizes whitespace/case and refuses duplicate or missing labels. Zero excludes a current sheet. Unmatched/excluded current sheets and unused revision sheets are listed; whole unmatched drawings are listed separately. More than 400 total current pages uses initially collapsed sheet tables to limit initial UI work.
4. Choose replacement or insert-before and enter a reason. Replacement requires identical effective CropBox, UserUnit and rotation for retained source PDF annotations. Equal geometry does not prove registration or engineering correctness. Insert-before retains old sheets and stamps them SUPERSEDED; existing historical navigation continues to point to old sheets.
5. Review the impact and select **Approve drawing set impact**, then **Apply reviewed drawing set**. Exact source SHA-256/page counts, operation, retained-markup policy, reason and selected pairs form a fresh source-bound plan for each document. Each job selects 1–100 one-to-one sheet pairs. Approval does not persist.

Mapping, file and setting edits invalidate approval and any prior downloadable archive. Pending reads, inspection and execution carry generation/abort guards so old results cannot become current. Closing, Escape or **Cancel drawing set** also cancels publication and retains no partial ZIP. Cancellation is checked between file reads, inspection/library stages and jobs; synchronous PDF copying, annotation generation and ZIP creation cannot be interrupted mid-call. Byte caps are not RAM or latency guarantees: original bytes, isolated snapshots, PDF object graphs and output copies may coexist.

## Save and resume mappings

After preparing and reviewing mappings, enter a reason and choose **Save drawing set plan**. The version 1 JSON plan contains the selected jobs' exact SHA-256/page counts, selected sheet pairs, common operation and reason. It excludes PDF bytes, filenames, paths, approval, results and execution state. Plans are limited to 1 MiB UTF-8, 20 jobs and 100 selected pairs per job. Source hashes and reasons can disclose project information; share plans deliberately.

To resume, reselect and prepare the original current/revision PDFs, then use **Import drawing set plan**. File names and selection order may change. Every selected job must resolve to exactly one inspected snapshot on each side with matching hash and page count. Duplicate identical snapshots on a side are ambiguous; remove duplicates and prepare again. Missing/mismatched sources, duplicate jobs, unsupported versions, mixed operation/reason or malformed mappings reject the entire import without changing mappings or settings. Each standalone job retains source PDF annotations; remove-markup plans from workspace workflows cannot be imported here.

A successful import restores the selected mappings and excludes other current drawings. Review all exclusions and source impact, then approve again. Starting an import discards previous approval and output. Approval cannot be granted while the plan read is pending. Mapping/settings/file changes, closing or cancellation invalidate delayed reads. Failed imports retain mappings/settings but require renewed approval. This resumes instructions only; completed/failed jobs, outputs and execution progress are not restored or automatically skipped. Reapplication runs all selected jobs against the original sources.

## Outputs and partial failures

Jobs run sequentially. Structural protection checks refuse apparent signed/certified, encrypted and XFA rewrites; this is not cryptographic signature validation. Donor layers/cross-page resource dependencies and other existing rewrite restrictions still apply. A processing failure produces a failed job result and later jobs continue. A stale source hash or invalid reviewed request rejects the whole request before output. Output byte-limit failures and other per-job failures remain explicit.

**Download revised drawing set ZIP** includes successful PDFs at fixed numeric paths such as `PDFs/0001.pdf`, `manifest.json` and formula-safe Unicode `summary.csv`. Failed jobs leave gaps in the numeric PDF paths. The manifest lists each requested job's success/failure, source fingerprints and labels, selected source-bound plan, unmatched pages, requested-operation journal evidence and, for successful jobs, output hash/page count/path/size. A failed job's journal describes the request; it does not assert a committed revision. An all-failed set can still produce its evidence archive. PDF inspection failures and unselected drawings appear in preparation/review UI and are not requested jobs in this archive.

The standalone workflow imports no engineering state; journal cleared-measurement/scale counts are zero. Source PDF annotations, including old measurement labels, remain at original coordinates and may be stale. It does not identify or clear legacy PDF measurement annotations. New revision sheets require independent calibration and qualified engineering review. Donor annotations/forms/actions are excluded. SUPERSEDED stamps are editable visual annotations, may cover drawing content and are not verified signatures or irreversible status controls. Source names and reasons in exported evidence can disclose project information.

## Limits and acceptance

- Up to 20 input PDFs per side, 64 MiB per PDF, 256 MiB combined selected PDF bytes; 1–200 pages per inspected source.
- Up to 20 jobs, 100 selected sheet pairs per job, 256 MiB of engine input copies and 128 MiB of retained PDF outputs/final archive. These are encoded-byte caps, not peak memory limits.
- Existing preservation is strongest for complete-primary document workflows. Broad catalog/tagged-structure/annotation interoperability, authorized professional drawing corpora, aggregate memory/throughput acceptance and installer/release verification remain open.
- Portable saved multi-file plans resume mappings only. No saved set library, automatic region/file-name syntax matching, resumable execution recovery, shared approvals, server collaboration, immutable revision archive or BCX compatibility.
