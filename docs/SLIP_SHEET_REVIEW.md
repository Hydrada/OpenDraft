# Reviewed slip-sheet replacement and revision journal

This is Project 1 Phase 4 progress. The original full completion gate remains open.

## Review workflow
Open the current drawing and a revision PDF. Activate the current drawing, choose Replace revised sheets, then select a revision document, pairing strategy and authored-markup policy. Unique normalized PDF labels and explicit page order reuse the batch matching rules. Duplicate or absent labels remain unmatched; manual choices are one-to-one. A zero selection leaves the target page unchanged. Review the reason, page mapping, affected authored-markup count and removal of calibration/measurement records, then approve. Changes revoke approval. The source snapshot and workspace model must still match at commit time.

Retain keeps authored markups at existing coordinates only when PDF.js viewBox, UserUnit and final rotation match exactly. This is a geometry prerequisite, not registration or engineering acceptance. Remove deletes authored markups on replaced pages; locked markups or layers reject removal. Every replaced page loses its scale calibrations and takeoff records, even if page dimensions match. Recalibrate and independently verify the replacement before takeoff. Source PDF annotations, hyperlinks and form widgets remain at their existing coordinates under either policy and require visual review, especially after geometry changes. Donor annotations/forms/navigation are not imported.

Current UI limits: two open PDFs, each at most 64 MiB and 200 pages, 1–100 selected replacements. No arbitrary source-file overwrite; Save PDF downloads an export. Original source bytes are retained in the workspace for undo and opt-in unencrypted recovery. Recovery retains at most 256 source objects per document and 512 MiB total; exceeding existing storage bounds reports a failure instead of claiming persistence. The whole replacement operation, authored markups, takeoff removal and journal entry commit as one history command. Normal 100-command undo bounds apply; recovery restores the current state, not prior undo commands.

## Document implementation
PageRef optionally identifies replacement content while retaining its base page identity. Full permutations of a single base source keep the existing target page object references and catalog. Donor Contents, Resources, MediaBox/CropBox/BleedBox/TrimBox/ArtBox, Rotate, UserUnit and transparency Group replace drawing data. Absent donor defaults are materialized so prior target inheritance cannot leak into the replacement. The existing target annotation array and document navigation/form structures remain. Page rotation deltas apply after donor rotation. Each materialization starts from immutable source bytes, avoiding repeated appearance/annotation accumulation.

Signed/certified-looking, encrypted and XFA rewrites reject through the existing structural guard; this is not cryptographic validation. Donor optional-content configurations and cross-page resource dependencies reject explicitly because they need a separately verified merge. Resource back-references to the selected donor page are repaired to the stable target reference. Partial extraction/deletion or multi-base merges retain the existing weaker catalog-preservation limitations; this milestone does not establish universal preservation.

## Revision evidence
A bounded local journal stores operation ID/time/reason, current pre-operation PDF SHA-256, revision-snapshot SHA-256, one-to-one target/revision page-number pairs, authored-markup policy and cleared scale/measurement counts. Entries participate in undo/redo, survive opt-in recovery and export as JSON. Page numbers describe the operation at that time; they are not stable sheet identifiers across later reordering. The journal is local mutable evidence, not a tamper-proof audit, signature or server history. Replacement recovery reconstructs immutable page references before installing a document so damaged donor page bounds fail during restore. A standalone saved PDF does not carry the editable workspace or journal; export the journal separately and use opt-in recovery for editable state.

## Acceptance and remaining scope
Tests cover content/geometry adoption, target page-reference/catalog/annotation preservation, source immutability, same-document swaps, repeated materialization, defaults/transparency, malformed/protected/layer-dependent donors, authored locks, reviewed takeoff clearing, source-hash evidence and browser undo/redo/recovery. Independent pypdf/PDFium/Pillow fixtures verify retained metadata/catalog/form/link/attachment/label objects and searchable replacement text. Full replacement content and unchanged-page rasters match independent sources with annotations suppressed; annotation retention is checked structurally. The checker explicitly applies parsed UserUnit because [pypdfium2 page rendering](https://pypdfium2.readthedocs.io/en/stable/_modules/pypdfium2/_helpers/page.html) does not incorporate it automatically. Consult TEST_RESULTS for exact current counts and failures.

Broader authorized PDF corpora, tagged-PDF structure relationships, donor layers/forms, arbitrary annotation transfer/alignment, multi-file/folder sets, saved batch plans, server revision history, tamper resistance, archival revision browsing and production performance remain open. No broad feature-parity claim or engineering acceptance is made.

Implementation and UI are independently created; its wider multi-document and reporting workflows remain gaps.
